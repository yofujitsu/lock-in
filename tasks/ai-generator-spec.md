# AI-генератор кастомных списков слов

> Статус: **черновик на согласование**. Ничего не реализовано до одобрения.

## 1. Цель

Добавить генерацию тематических списков слов по произвольному запросу через
облачный LLM (bring-your-own-key). Использует уже заложенный шов `TextSource`:
AI — это «производитель контента», который кладёт результат в кеш, а синхронный
движок набора читает кеш. Движок, метрики и существующие типы контента не меняются.

## 2. Подтверждённые решения (из брифа)

- **Где модель:** облачный LLM с ключом пользователя (BYOK).
- **Что генерируем (v1):** только кастомные списки слов (режим `words`).
- **Хранение ключа:** `tauri-plugin-store`, настройка в UI.

## 3. Архитектура и поток данных

```
UI (Words → Topic: Custom → ввод темы → «Generate»)
   │  invoke("generate_word_list", { lang, topic })
   ▼
Rust-команда `generate_word_list`          ← читает конфиг из Tauri store
   │  reqwest POST  {baseUrl}/chat/completions  (модель = model, ключ = apiKey)
   ▼
LLM отвечает JSON-списком слов
   ▼
Валидация/нормализация (чистая TS-функция, юнит-тестируется):
   lowercase · одиночный токен · [a-z]+ / [а-яё]+ · дедуп · cap 100
   ▼
Кеш (Tauri store: custom_lists["{lang}:{topic}"] = string[])
   ▼
Синхронный `generateWords(lang, count, rng, customTopic)` читает кеш
   ▼
Обычный набор текста (движок/метрики без изменений)
```

Асинхронность заперта в одном месте: команда генерирует и кладёт в кеш; дальше всё
синхронно. Существующий `TextSource`/`STATIC_SOURCE` не ломается — кастомная тема
это отдельная размерность (`customTopic: string`), а не новый `WordTopic`.

## 4. Конфиг и хранение ключа

- Новый store-файл `settings.json` через `tauri-plugin-store`:
  ```json
  { "aiBaseUrl": "https://api.openai.com/v1", "aiModel": "gpt-4o-mini", "aiApiKey": "" }
  ```
- UI настройки: поля base URL, модель, API-ключ (парольный ввод), в панели настроек.
- Ключ хранится локально в app config (plaintext) и отправляется **только** на
  настроенный `aiBaseUrl`. Для локального десктоп-приложения это приемлемо; в спека
  фиксируем, что ключ не логируется и не попадает в историю/дискорд.

## 5. Провайдер

Один код — **OpenAI-совместимый** `POST /v1/chat/completions` (де-факто стандарт).
Меняя `aiBaseUrl`/`aiModel`, тот же код работает с OpenAI, Groq, OpenRouter и —
позже — с локальным Ollama (`http://localhost:11434/v1`), без переделки.

## 6. Генерация и валидация

- Промпт: «верни только JSON-массив из N одиночных слов на тему T, язык L,
  без знаков препинания и пробелов».
- Ответ парсится, затем чистая функция `sanitizeWordList(raw, lang)`:
  lowercase, отброс некорректных символов/пробелов, `[a-z]+` / `[а-яё]+`,
  дедуп с сохранением порядка, cap 100.
- Пустой/невалидный ответ → ошибка с сообщением в UI.

## 7. Кеширование

- Сгенерированные списки сохраняются в store `custom_lists` и переиспользуются:
  повторный выбор той же темы не вызывает LLM повторно.
- Кнопка «Regenerate» — перегенерировать выбранную тему (сбрасывает кеш темы).

## 8. UI (Practice, режим Words)

- В селектор **Topic** добавляется пункт **Custom**.
- При выборе Custom: поле ввода темы + кнопка **Generate** + индикатор загрузки /
  ошибка. После успеха — список доступен для набора, тема остаётся выбранной.
- Настройки AI (base URL / модель / ключ) — в существующей Style-панели (или
  отдельной секции настроек), сохраняются в store.

## 9. Транспорт: Rust или JS (решение)

- **Рекомендуется: HTTP в Rust (`reqwest`), ключ читается в Rust из store.** Нет
  CORS/origin-проблем webview, ключ не попадает в JS. Цена: +зависимости
  `reqwest`/`tokio` и `tauri-plugin-store`, тонкая Rust-команда.
- Альтернатива (меньше Rust): `fetch` из JS, ключ из store через JS-API плагина.
  Цена: риск CORS/нестандартного origin webview, ключ в памяти JS.

Спеку пишу под рекомендуемый вариант (Rust). Если нужен минимум Rust — поменяем
п. 9 на JS-fetch до реализации.

## 10. Тесты (TDD)

- `sanitizeWordList` — юнит-тесты (валидные/мусор/дедуп/cap/алфавит).
- Парсинг ответа LLM (строгий JSON, невалидный JSON, не-массив).
- Кеш: чтение/запись/повтор без лишнего вызова (store инъектируется).
- Rust-команда — тонкая; HTTP-клиент за швом (для тестов мокабелен), юнит-тестов на Rust не требуем.
