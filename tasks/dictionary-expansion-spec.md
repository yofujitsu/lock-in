# Расширение словарей и тематические режимы

> Статус: **черновик на согласование**. Ничего не реализовано до одобрения этой спецификации.

## 1. Цель

Расширить контент тренажёра тематическими режимами набора, добавить пунктуацию
в тексты (предложения, цитаты, отрывки) и заложить чистый шов под будущий
AI-генератор. Сейчас поставляется только pre-bundled контент.

## 2. Подтверждённые требования (из брифа)

- **Источник контента:** pre-bundled open-source (сейчас) + шов под AI (позже) — «hybrid».
- **Объём:** курированный набор — качество важнее количества, без мусора и лишнего форматирования.
- **Категории:** цитаты, случайные предложения (с пунктуацией), короткие отрывки/статьи, тематические списки слов.
- **Языки:** EN и RU.
- **Пунктуация обязательна** — сейчас в предложениях её нет, это путает.

## 3. Модель данных

### 3.1 Типы контента

`ContentType` расширяется с `'words' | 'sentences'` до:

```ts
export type ContentType = 'words' | 'sentences' | 'quotes' | 'passages';
```

- `words` — поток случайных слов (как сейчас), с опциональной **темой** (см. 3.2).
- `sentences` — случайные предложения **с пунктуацией** (апгрейд текущих голых фрагментов).
- `quotes` — цитаты (литературные / мотивационные / про программирование) с пунктуацией.
- `passages` — короткие отрывки (2–4 предложения каждый) для длинного набора.

### 3.2 Темы для слов

Новая размерность `WordTopic` (только для режима `words`):

```ts
export type WordTopic = 'general' | 'programming' | 'tech'; // стартовый набор, расширяемый
```

- `general` — текущий частотный список из 1500 слов (по умолчанию, поведение не меняется).
- `programming`, `tech` — курированные тематические списки.

### 3.3 Структура словаря

```ts
export interface Quote {
  text: string;        // текст цитаты с пунктуацией (то, что набирается)
  source: string;      // автор/источник (не набирается, показывается подписью)
}

export interface Dictionary {
  words: Record<WordTopic, string[]>; // general + тематические списки
  sentences: string[];                // предложения с пунктуацией
  quotes: Quote[];                    // цитаты с атрибуцией
  passages: string[];                 // отрывки с пунктуацией
}
```

## 4. Файлы данных и источники (курированные, лицензионно чистые)

Все данные — офлайн, внутри приложения, в `src/data/`. Новые файлы:

| Файл | Содержимое | Целевой объём (на язык) | Источник / лицензия |
| --- | --- | --- | --- |
| `quotes-en.json` / `quotes-ru.json` | `[{text, source}]` | 40–60 цитат | общественное достояние (классика, фольклор, пословицы); атрибуция в `source` |
| `sentences-en.json` / `sentences-ru.json` | `string[]` | 60–100 предложений | курируются вручную (естественные фразы) + пословицы; без копирайта |
| `passages-en.json` / `passages-ru.json` | `string[]` | 15–25 отрывков | короткие отрывки из общественного достояния (Gutenberg / русская классика) |
| `topics-en.json` / `topics-ru.json` | `{ programming: string[], tech: string[] }` | 60–120 слов на тему | курируются вручную (термины, общеупотребительные) |

- `words-en.json` / `words-ru.json` остаются как `general`.
- Каждый источник фиксируется в `src/data/README.md` (атрибуция + лицензия).
- Содержимое пишется напрямую в JSON (курирование), без скрипта-генератора.
- Правила качества данных (проверяются тестом): в конце каждого предложения/цитаты/отрывка
  есть пунктуация, нет двойных пробелов, нет ведущих/хвостовых пробелов.

## 5. Пунктуация и нормализация в движке

Пунктуация печатается как обычные символы. Но типографские знаки из курированных текстов
(`—`, `«…»`, `“…”`, `’`) нельзя набрать одной обычной клавишей. Поэтому в движок добавляется
**нормализация эквивалентных символов** — маленькая чистая функция, чтобы ASCII-нажатие
совпадало с типографским знаком:

```ts
// engine.ts — новая чистая функция + использование в handleKey
const EQUIVALENTS: Record<string, string> = {
  '“': '"', '”': '"', '„': '"', '«': '"', '»': '"', // двойные кавычки → "
  '’': "'", '‘': "'",                                 // одинарные → '
  '–': '-', '—': '-',                                 // тире → -
};

export function equivalent(a: string, b: string): boolean {
  const norm = (c: string) => EQUIVALENTS[c] ?? c;
  return norm(a) === norm(b);
}
```

- В `handleKey` сравнение `key === expected` заменяется на `key === expected || equivalent(key, expected)`.
- Отображение и статусы не меняются: цель `«` при нажатии `"` помечается `correct`, на экране
  остаётся `«` (поведение «умных кавычек»).
- Существующие ASCII-тесты не затрагиваются; для нормализации пишутся новые тесты.
- `ё`/`е` остаются строго разными (вне scope).

## 6. Генерация текста (`buildText` и генераторы)

`dictionary.ts` получает функции-генераторы (все детерминированные по `rng`):

```ts
generateWords(lang, count, rng, topic?)   // topic = 'general' по умолчанию
generateSentences(lang, count, rng)
generateQuotes(lang, count, rng)          // возвращает текст + атрибуцию
generatePassages(lang, count, rng)
```

Стратегия длины в `buildText` (эвристики, настраиваемые):

| Режим | Free (`seconds === null`) | Timed |
| --- | --- | --- |
| words | 80 слов | `max(80, min(seconds*2, 400))` (как сейчас) |
| sentences | 4 | `max(4, ceil(seconds/12))` (как сейчас) |
| quotes | 3 цитаты | `max(3, ceil(seconds/20))` |
| passages | 2 отрывка | `max(2, ceil(seconds/30))` |

- `buildText` возвращает `{ text, attribution? }` — атрибуция только для цитат.
- В timed-режиме текст генерируется «с запасом»; сессия всё равно обрывается таймером.

## 7. UI (Practice)

- Сегмент **Text** расширяется до 4 кнопок: `Words | Sentences | Quotes | Passages`.
- При `Words` появляется сегмент **Topic**: `General | Programming | Tech` (по умолчанию General).
  Для остальных типов селектор темы скрыт.
- Язык EN/RU и режим (echo/free/timed) без изменений; echo-режим не затрагивается.
- Атрибуция цитаты показывается подписью под текстом набора (не входит в набираемый текст);
  в v1 в экране результатов атрибуция не дублируется.

## 8. История и статистика

- `HistoryEntry.contentType` уже `string` — новые значения `'quotes' | 'passages'` совместимы,
  миграция не нужна (старые записи остаются `'words' | 'sentences'`).
- Добавляется общий помощник `contentTypeLabel(contentType)` и используется в
  `Results.tsx` / `Profile.tsx` вместо текущих инлайн-проверок.
- `statsByContentType` расширяется: порядок `['words','sentences','quotes','passages']` + подписи.

## 9. Шов под будущий AI-генератор (hybrid, сейчас НЕ реализуем)

Тонкий шов без преждевременной абстракции — доступ к данным за одним объектом:

```ts
export interface TextSource {
  words(lang: Language, topic: WordTopic): string[];
  sentences(lang: Language): string[];
  quotes(lang: Language): Quote[];
  passages(lang: Language): string[];
}

export const STATIC_SOURCE: TextSource = { /* читает bundled JSON */ };
```

- Генераторы принимают `source` (по умолчанию `STATIC_SOURCE`).
- Будущий AI-генератор = отдельный модуль, реализующий `TextSource` (асинхронно), включается флагом.
- Потребители (`App`, генераторы) не меняются при добавлении AI.
